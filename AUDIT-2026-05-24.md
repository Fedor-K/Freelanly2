# Freelanly + content-autopilot — Full Audit (2026-05-24)

Scope: Freelanly2 (Next.js app) + content-autopilot (Python blog-posting pipeline) as one system.
Dimensions: correctness/bugs, security, architecture/quality, SEO/performance.
Method: 4 parallel review agents; **all CRITICAL security + feature-breaking items were re-verified by hand** (marked ✓verified).

Intentional decisions (NOT treated as bugs): alerts suspended, `/jobs|/company|/country` removed, Postal-only email, 30-day job deletion.

---

## CRITICAL — exploitable or breaks the core feature

### Security

**C1. `admin/users/[id]` PATCH & DELETE are completely unauthenticated** ✓verified
`src/app/api/admin/users/[id]/route.ts:8,42` — no `checkAdminSession`.
`PATCH {plan:"PRO"}` → free PRO for anyone. `DELETE` → permanently deletes any user (+ alerts/applications/sessions/accounts). Exploit: `curl -X PATCH https://freelanly.com/api/admin/users/<id> -d '{"plan":"PRO"}'`.
Fix: add `const e = await checkAdminSession(request); if (e) return e;` to both. Better: enforce admin auth for `/api/admin/*` in `src/middleware.ts`.

**C2. ~9 more `admin/*` routes have no authorization** ✓verified (pattern)
`admin/chat`, `admin/dashboard`, `admin/cohorts`, `admin/funnel`, `admin/users/[id]/activity`, `admin/users/[id]/send-portal-link`, `admin/sources/[id]{,/run,/tags}`.
Leaks: user emails/IPs/cities (chat), MRR/PRO counts/funnels (dashboard/cohorts/funnel); lets anyone send Stripe portal emails to arbitrary users and trigger scrapers (cost/abuse).
Fix: centralize admin auth in middleware for `/api/admin/*`.

**C3. PayPro webhook signature bypass → free PRO** ✓verified
`src/app/api/paypro/webhook/route.ts:58,66` — `if (!testMode && hash)` / `if (!testMode && signature)`. `testMode` and the signature fields all come from the attacker-controlled body. Setting `TEST_MODE=1` **or** omitting `HASH`/`SIGNATURE` skips all verification; `PAYPRO_IPS` allowlist is never enforced. Exploit: `POST /api/paypro/webhook` form `IPN_TYPE_ID=1&CUSTOMER_EMAIL=victim&ORDER_ID=1&TEST_MODE=1` → PRO.
Fix: require a valid signature for all non-test events; don't let the body decide test-mode; enforce IP allowlist; `timingSafeEqual`.

**C4. Hardcoded PayPro secrets in source** ✓verified
`src/lib/paypro.ts:10-11` — `secretKey ... || 'sMuqVcckLz'`, `validationKey ... || 'v79nsiatA45DvjRzx415-0KYg190nb'`. These let anyone forge valid PayPro hashes/signatures (defeats the C3 fix). **Rotate both keys now**, remove the fallbacks, require the env vars.

**C5. Resend webhook signature verification hard-disabled** ✓verified
`src/app/api/webhooks/resend/route.ts:125` — `if (false && ...)`. Unauthenticated; a forged `email.complained` with attacker-chosen `to` sets `unsubscribedFromMarketing=true` for any user. Fix: remove `false &&`; `verifySvixSignature` already exists and is correct.

**C6. Stored XSS via `dangerouslySetInnerHTML` on AI/scraped content**
`src/app/blog/[slug]/page.tsx:211` (`marked.parse(post.content)` — blog body is AI-generated via the autopilot, stored verbatim, `marked` does not sanitize), `dashboard/discovery/[id]/page.tsx:87,117,136`, `components/opportunities/ProjectDetailNew.tsx:105`, `components/app/TemplatesClient.tsx:185`. Scraped `description`/`replyText` (from the unauthenticated inbound-reply webhook) and AI markdown can carry `<img onerror=…>` → JS exec on public blog + logged-in dashboards.
Fix: sanitize with `isomorphic-dompurify` (or marked + sanitizer) before render; sanitize `replyText`/`description` server-side.

### Feature-breaking (the whole point of content-autopilot is SEO blog traffic)

**C7. Sitemap never emits blog posts** ✓verified
`src/app/sitemap.ts:29` — `where: { published: true }`, but `BlogPost` has no `published` field (it's `status`). Prisma throws; the `try/catch` at :38 swallows it → `blogPages = []` always. **Every autopilot post is absent from the sitemap.**
Fix: `where: { status: 'PUBLISHED' }`; also add `/blog/category/[slug]` pages.

**C8. ToC + heading anchors empty for every autopilot (Markdown) post** ✓verified (code path)
`src/app/api/blog/create/route.ts:189,247` — `extractTableOfContents`/`addHeadingIds` use HTML `<h2>/<h3>` regexes, but the autopilot sends Markdown (`## …`). Result: `tableOfContents=[]`, headings stored with no `id=`. At render, `marked.parse()` (`blog/[slug]/page.tsx:211`) emits `<h2>` without IDs → ToC widget never shows, anchor links dead. (FAQ regex works on Markdown, so FAQ schema is OK.)
Fix: convert Markdown→HTML server-side in `/api/blog/create` before extraction (store HTML), or make the regexes Markdown-aware + add a custom `marked` heading renderer that injects `id`.

## HIGH

**H1. Cron auth bypass via spoofable header** ✓verified
`src/lib/cron-auth.ts:42-46` — `x-replit-cron: true` authorizes any request (app is on Vercel, not Replit). Also `?token=<CRON_SECRET>` (:33) leaks the secret into logs/Referer; comparisons are `===` not timing-safe. Anyone can trigger `process-auto-apply` (sends real recruiter emails as users), `submit-to-index`, `post-to-social`, `send-*`. Fix: delete Method 3 (query) and Method 4 (replit); Bearer only; `timingSafeEqual`.

**H2. Destructive debug endpoint with guessable key**
`src/app/api/debug-queue/route.ts:9` — `SETUP_KEY='fr33lanly-setup-2026'`; `?key=…&fix=true` deletes all `importTask` / pending `alertNotification` rows. Delete the route or gate behind cron/admin auth.

**H3. Unauthenticated webhooks driving DB writes/emails**
- `webhooks/inbound-reply/route.ts:50` — forge recruiter replies, inject `replyText` (→ C6 XSS), trigger user emails + their `notifySlackUrl`.
- `webhooks/telegram-bot/route.ts:25` — no secret-token check; `direct_<prefix>` match binds attacker's Telegram chat to a victim account.
- `api/unsubscribe/route.ts:39` — token only checked `if (token)`; omit it to unsubscribe any email + deactivate their alerts.
- `webhooks/elasticemail`, `webhooks/email-bounce` — unauth, can inflate `emailBounceCount` (suppresses a user's emails).
Fix: verify shared secret/signature on each; require unsubscribe token always.

**H4. FREE auto-apply daily limit incremented but never enforced or reset**
`src/services/auto-apply-processor.ts:404` increments `freeAppliesUsedToday`, but the processor never checks a cap nor resets daily (only `quick-apply` does). FREE users get unlimited auto-applies through the queue path. Fix: enforce + reset the cap in `processAutoApplyQueue`.

**H5. Reply-checker false positives**
`src/services/reply-checker.ts:249,262` — IMAP `SEARCH FROM+SINCE` matches any email from that sender (newsletters, autoresponders) and treats sequence numbers as UIDs. Flips application → REPLIED/INTERVIEW and emails the user on wrong content. Fix: `UID SEARCH`+`UID FETCH`, constrain by subject/`In-Reply-To`.

**H6. PayPro duplicate-order guard is structurally broken**
`src/app/api/paypro/webhook/route.ts:82` — `findFirst` returns an arbitrary paypro row, only dedupes if *that* row's `orderId` matches. Duplicate IPNs create duplicate PRO-upgrades/unlocks. Fix: query `details.orderId == orderId` directly.

**H7. `submit-to-index` cron pushes dead URLs to Google/IndexNow, never blog posts**
`src/app/api/cron/submit-to-index/route.ts:87-126` — submits `/jobs/*`, `/company/*/jobs/*` (all 301→signin) to Google Indexing API (200/day quota) + IndexNow; blog posts never submitted. Fix: drop job/company URLs; submit `/blog/<slug>` for PUBLISHED posts.

**H8. Dead email-provider abstraction defaults to Resend**
`src/lib/email/index.ts` imports 4 dead providers and falls through to Resend (dummy key) if `EMAIL_PROVIDER` is unset; `src/lib/auth.ts:24` uses `next-auth/providers/resend` with `'re_dummy_key_not_used'` as an OTP shell. If the env var is ever unset, sign-in/OTP silently break. Fix: collapse `email/index.ts` to Postal-only; switch auth provider to nodemailer/generic.

**H9. Stale/heavy dependencies with prod impact**
- `@anthropic-ai/sdk` in `package.json` — **zero imports** in the app (only the Python project uses Anthropic). Remove.
- `puppeteer*` — `lever-discovery.ts` notes it "doesn't work on Vercel"; the `discover-lever` Vercel cron silently no-ops → Lever discovery broken in prod. Move to Hetzner or use HTTP; drop from deps.
- `google-ads-api` (gRPC native) called inside the Stripe webhook (`uploadOfflineConversion`) — a failure there can break the payment webhook. Wrap in try/catch / background it.

**H10. Blog perf: list pages fetch full `content @db.Text` per card**
`src/app/blog/page.tsx:36`, `blog/category/[category]/page.tsx:24` — `include:{category:true}` (no `select`) pulls full markdown for every card. Add explicit `select`. Also `blog/[slug]/page.tsx` does 3 sequential DB round-trips (metadata fetch + page fetch + blocking `viewCount` update) — wrap fetch in React `cache()`, fire-and-forget the increment.

## MEDIUM

- **Stripe webhook**: no top-level idempotency on `event.id`; duplicate `checkout.session.completed` hits the `RevenueEvent.stripeEventId` unique constraint (uncaught) → 500 → infinite Stripe retries (`stripe/webhook/route.ts:243`). Also `current_period_end` read via cast may be undefined on newer API versions → `subscriptionEndsAt` silently null.
- **Auto-apply**: module-level `aiMatchCache` never cleared (unbounded growth on warm worker; key = top-5 skills + location → cross-user collisions) `auto-apply-processor.ts:634`. Queue dedup check-then-create race for same-recruiter+title (no DB constraint).
- **`blog/[slug]` `generateMetadata` lacks `status:'PUBLISHED'`** → serves meta for DRAFTs that 404 in body (`page.tsx:66`).
- **Blog titles not run through `truncateTitle()`** (`blog/[slug]:75`, category:63); autopilot generates ≤70-char titles vs Google's ~60.
- **Breadcrumb category link/JSON-LD uses `/blog?category=`** instead of canonical `/blog/category/[slug]` (`blog/[slug]:133,357`).
- **Blog category pages missing from sitemap**; `/auth/signin` is in sitemap (priority 0.85) and not noindex.
- **`sitemap.ts` sets both `force-dynamic` and `revalidate=3600`** (conflict; regenerates every crawl). Blog list pages have no `revalidate`.
- **Dead code to remove** (post-pivot): `src/components/jobs/*` (16 of 17 unused) + `salary-insights`/`salary-estimation`/`salary-base`/`salary-coefficients` chain; armed-but-suspended alert system (`alert-notifications.ts` 740L, `alert-matcher.ts`, `AlertsList.tsx` 632L, `process-instant-alerts`, `cleanup-stale-alerts`); `RegistrationForm.tsx.backup`; `CrossSellExitPopup.tsx` (unused, links to dead pages).
- **Dead/duplicate schema models**: `Application` (old) vs `AutoApplication` (new) — 3 call sites count the wrong one (metrics silently wrong); `LandingPage`, `AlertEmailFeedback`, `ReengagementEmail` unused; `EmailEvent` goes stale (Postal not Resend) but still powers admin email-stats UI; `User.password` never read; `AlertFrequency` enum has one value.
- **16 cron routes have no Vercel/scheduler registration** — split-brain (Hetzner calls some directly, undocumented). Trial/winback/activation emails may not be sending. Document which Hetzner runs; delete the rest. Two crons use inline bearer checks instead of `isCronAuthorized` (`send-daily-recap:35`, `cleanup-stale-alerts:13`).
- **`/api/chat`** trusts client-supplied `userId`/`userEmail`/`userStatus` (`chat/route.ts:255`) — analytics poisoning / behavior change. Derive from session.
- **`blog/create` shares `CRON_SECRET`** with crons + admin fallback (`admin-auth.ts:16`); one leak = blog-publish + cron + admin. Non-timing-safe compare. Consider a dedicated publish secret.
- **`ProjectPageClient.tsx:612`** (main conversion page) links to dead `/jobs/<category>` → 301 to signin for logged-in users.
- **content-autopilot SSRF-adjacent**: `image_gen.py` `urlopen` on the DALL-E URL (OpenAI-sourced, low risk now) — add host allowlist.

## content-autopilot specifics

- `publisher.py:157` — hard `data["post"]["id"]` indexing → opaque `KeyError` on malformed 200. Validate shape, raise descriptive error.
- `work_queue.py` — no `__main__` smoke test (SPEC requires it); `failed` items never retried and their topic-slug stays in the dedup set → permanently lost. Either retry failed, or exclude failed slugs from dedup.
- `researcher.py:375` — title prompt says ≤70 chars; should be ≤60 + add `_truncate(title,60)` in `_build_article` (ties to the blog truncateTitle gap).
- `publisher.py` doesn't send `ogImageAlt` (image_gen produces good alt text; blog falls back to title). Add `ogImageAlt` to payload + `CreateBlogPostRequest` + create route.
- `planner.py:63` — cosmetic double-brace `{{ … }}` around the category block.
- **Otherwise the pipeline is clean**: typed dataclass contracts, prompt caching in planner+researcher, tenacity retries, best-effort image handling, current model IDs, correct `/jobs/*` internal-link ban.
